## 1. 목표와 일정

- 사용자: 흰다리새우 실내 양식장 초보 운영자·급이 관리자.
- 해결: 바닥 섭식이라 육안 확인이 어렵다 → 수중 음향으로 평소 대비 섭식 반응 감소·지연을 정량화해 다음 급이 전 점검 근거를 준다. **질병 진단·원인 단정은 하지 않는다.**
- 결과물: 웹 서비스 + API + 대시보드. MVP = WAV 업로드 → 분석 → 그래프 → 점검 알림. 실시간 하이드로폰·자동 급이 제어는 후속.
- KPI(초기 제안, 파일럿 후 조정): 클릭 F1 ≥ 0.85, CPM MAE 신호처리 Baseline 대비 20%↓, 정상 세션 오경보율 ≤ 10%, 40분 WAV 분석 ≤ 5분.
- 기간 2026-10-16 ~ 11-27. MVP 우선 구현 ~11-15.

## 2. 실험 설계 v2 (데이터의 실제 모양)

- 소음 조건 2개 × 독립 수조 3개 × 4일 × 수조당 하루 1회 = **G(t) 24개** (조건별 12개).
  - 조건 1 소음 차단: 수조 A1·A2·A3 / 조건 2 운영 소음(펌프·에어레이션 가동): B1·B2·B3.
  - 계획안의 "하루 5회 급이"는 **삭제됨**.
- 세션 = 급이 전 10분 + 급이 후 30분, 끊김 없는 **40분 WAV 1개**. 급이 시각 = 0분.
- **독립 반복은 수조 3개**뿐이다. 같은 수조의 4일은 반복측정 → 24개(또는 12개)를 독립 n 으로 취급하지 않는다.
- 실제 이상 사례가 없다 → 결과는 "정상 G(t) 재현성"과 "소음 조건별 검출 안정성"으로 표현. 이상 탐지 평가는 합성 이상으로만.
- Day 1 게이트: Day 1 자료로 후보 펄스 검출 설정(주파수·지속시간·간격·SNR)을 정하고 **Day 2–4 에는 바꾸지 않고** 적용.
  - 진행: 급이 후 펄스가 반복적으로 늘고, 장비·투입 충격만으로 설명되지 않으며, 여러 수조에서 같은 설정으로 G(t) 산출.
  - 재점검: 소음 조건에서만 과다 검출, 설정 조금만 바꿔도 수가 크게 변함, 여러 펄스가 한 사건으로 합쳐짐.
  - 보류: 급이 전후가 안 갈리거나 장비·충격음이 대부분.

### 세션마다 남기는 기록

| 시점 | 기록 |
|---|---|
| 녹음 시작 | 파일명, 시작 시각, 수조 ID, 소음 조건 |
| 급이 | 급이 시작 시각, 투입량(g), 투입 소요시간 |
| 급이 후 30분 | 충격·작업·장비 변화 등 특이사항(사건 시각) |
| 종료 | 종료 시각, 잔여 사료 회수 여부·미회수 사유 |
| 저장 | 누락 여부, 파일 길이, 백업 위치 |
| 시작·종료 | 수온·염분·DO·pH (허용범위 이탈 표시) |
| 수조 | 개체수, 대표 체중, 생체량, 사료 제조사·lot·형태, 센서 위치(사진) |

### 섭취량 자료 (보조)

- 겉보기 섭취량 = 투입량 − 회수 잔여량(건조질량). 용출·파편 손실 포함 → **실제 섭취량으로 단정하지 않음**.
- 회수 실패·미보정 세션은 그대로 표시, 0 으로 채우지 않는다.
- 용도: Peak·AUC 와의 관계를 보조적으로 확인. UI 의 "추정 사료 소비량"은 선택 기능이며 이 한계를 함께 표시한다.

## 3. 지표 정의

| 지표 | 정의 | 출처 |
|---|---|---|
| G(t) | 클릭(후보 펄스) 시각을 60초 단위로 집계, 급이 = 0분 정렬 | 공통 |
| 기준선 CPM | 급이 전 10분 CPM 수준·안정성 | 설계서 |
| Peak CPM | 급이 후 최대 CPM | 공통 |
| 초기 10분 AUC | 급이 후 0–10분 누적 | 계획안 |
| 30분 AUC | 급이 후 30분 누적(총 음향활동량) | 설계서 |
| 반응 시작 지연 | 급이 후 클릭이 늘기 시작한 시점 | 계획안 |
| Peak 도달 시간 | 급이 → 최대값까지 | 공통 (반응 시작 지연과 구분) |
| 재현성 | 같은 수조 4일간 곡선 형태 유지 | 설계서 |

## 4. 모델

**모델 A — 클릭 검출**: 대역통과 → 노이즈 억제(펌프·기포·저주파) → 정규화 → 클릭 시각 → 60초 CPM → G(t).
- Baseline: 신호처리(Band-pass, STFT, 에너지·피크). 주력 후보: 짧은 STFT/Log-Mel + CNN(클릭 vs 소음). CLAP 등 사전학습 인코더는 확인 후 추가 비교.
- 평가: 사람이 표시한 클릭 시각을 정답으로 허용오차 내 1:1 매칭 → Precision/Recall/F1, 1분 CPM MAE(Baseline 대비), 소음 조건별 비교.
- 라벨: 파형·스펙트로그램으로 개별 클릭 시각 표시. 판별 불가 구간은 정답으로 쓰지 않는다. 일부 이중 검수.

**모델 B — 이상 탐지(통계 기반)**: 정상 세션을 급이 시각에 정렬해 분 단위 평균 μ(t)·표준편차 σ(t)(또는 중앙값·분위수).
- 같은 경과 시간끼리 비교해 자연 감쇠를 이상으로 오인하지 않는다.
- 점수: `Score = w1·z_peak + w2·z_AUC + w3·z_delay + …` (+ 곡선 이탈), 등급 normal/watch/alert. 가중치·임계값은 검증 데이터로 정한다.
- 크기·밀도·급이량·소음 조건 차이가 크면 기준을 분리(→ 수조별/조건별 기준).
- 평가: 정상 오경보율(Leave-One-Out), 합성 이상(Peak 감소·초기 AUC 감소·지연·조기 감쇠) 유형·강도별 탐지율, 지표별 민감도.
- 기준·임계값에 쓴 세션은 평가에서 제외. 같은 원본에서 만든 변형이 기준용·평가용에 나뉘어 들어가지 않게 한다.

**전체 시스템 평가**: 모델 A 가 예측한 CPM 으로 모델 B 를 돌린 성능, 처리 시간, 소음 환경별 강건성.

## 5. 서비스 시안 (이미지)

- 화면: 대시보드 / 분석하기(수조·급이 시각·급이량 입력 → WAV 업로드 → 분석 시작) / 수조 관리 / 급이 기록 / 알림 내역 / 설정.
- 결과 화면: 판단 결과(예: "섭식 활동 저하 감지"), 현재 Peak·초기 10분 AUC·이상 점수(임계값 대비) 카드, G(t)와 정상 범위(±1σ) 겹친 그래프, 주요 지표 비교표(정상 기준·현재·변화율), 인사이트 문장, 분석 이력.
- API 예시: `POST /api/v1/analyses`, `GET /api/v1/analyses/{id}`, `GET /api/v1/analyses/{id}/results`, `GET /api/v1/tanks`, `POST /api/v1/feeds`, `GET /api/v1/alerts`.
- DB(PostgreSQL 후보) 테이블 예시: recordings(파일 경로·수조·급이 정보), analyses(상태·시각), click_events, cpm_series, feed_metrics(Peak·AUC 등), alerts.
- 외부 서비스 시안의 "LangChain + LLM 인사이트"는 **원본 음향·시설 정보 외부 전송 금지** 규칙과 충돌할 수 있다 → 기본은 로컬 템플릿 문장, LLM 은 집계 지표만 보내는 선택 기능으로만 검토.
