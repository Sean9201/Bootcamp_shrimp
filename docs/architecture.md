# 아키텍처 개요

```
[하이드로폰 WAV] ──► data_pipeline ──► (정리된 녹음 + 메타 + 라벨)
                                             │
                                             ▼
                                            ai  ── 클릭 검출(모델 A) → G(t) → 활동 지표
                                             │      이상 탐지(모델 B: 정상 기준 비교)
                                             ▼
                                         backend ── REST API · DB · 비동기 분석 · 알림
                                             │
                                             ▼
                                        frontend ── 대시보드 · 업로드 · 결과 · 알림 화면
```

## 영역별 책임

| 영역 | 책임 | 산출물 |
|---|---|---|
| data_pipeline | 녹음 수집·검수, 메타데이터, 클릭 라벨, 합성 데이터, 학습/검증 분할 | `data_pipeline/data/` (git 제외), 데이터셋 버전 표 |
| ai | 검출기·이상 탐지 로직, 학습, 평가(F1, CPM MAE, 오경보율) | 파이썬 패키지 `shrimp_ai`, 모델 가중치(git 제외), 평가 리포트 |
| backend | 업로드·급이 이벤트·분석 실행·결과 저장·알림 API | FastAPI 서버, DB 마이그레이션 |
| frontend | 관리자 화면 | React 앱 |

## 결정 기록

중요한 결정은 아래 형식으로 덧붙인다.

| 날짜 | 결정 | 이유 |
|---|---|---|
| 2026-11-02 | 영역별 폴더 + 영역별 브랜치 구성으로 새 저장소 시작 | 개인 작업으로 전환, 영역별로 나눠 구현 |
| 2026-11-02 | 데이터 구조는 실험 설계서 v2 기준(2조건 × 3수조 × 4일, 하루 1회, 40분 WAV) | 계획안의 하루 5회 급이안은 설계서 v2 에서 삭제됨 |
| 2026-11-02 | 평가·정상 기준은 수조를 독립 단위로 다룬다(4일은 반복측정) | 독립 생물학적 반복이 수조 3개뿐 |
| 2026-11-02 | 인사이트 문장은 외부 LLM API 로 생성. 보내는 것은 집계 지표뿐, 실패 시 템플릿 문장 | 구성이 가장 단순. 원본 음향·시설 정보 외부 전송 금지는 유지 |
| 2026-11-02 | 소음 조건 B(운영 소음)는 "소음이 있어도 안정적으로 동작하는가" 검증용 | 사용자 결정 |
| 2026-11-02 | 입력은 WAV 업로드. 엔진은 파일을 시간순 청크로 잘라 순서대로 처리(실시간 입력과 같은 구조) | 실시간 하이드로폰 연결은 기간 내 불가, 시연은 파일 재생 방식 |
| 2026-11-02 | 겉보기 섭취량(추정 사료 소비량)은 MVP 에서 제외 | 근거 데이터 부족 |
